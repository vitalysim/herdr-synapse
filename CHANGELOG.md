# Changelog

## 0.12.0 (2026-09-08)

- An agent that needs you now gets you. Measured on the team this was built against, over three days: 88 posts addressed to the operator, ten of them actually waiting on a decision, **six of those never answered by anyone**, and all four that were answered were answered by *other agents* — one of which overrode a genuine pre-submission halt with "STOP ORDER IS STALE". The loop was not merely un-notified; it was being closed by the wrong party.
- `herdr-synapse asks` lists what is waiting on you, and the notifier opens a popup you answer in. It is **one popup for the whole queue**, not one per post: Herdr allows exactly one popup at a time and a popup has no pane id to address, so 88 posts could never be 88 modals. Type and Enter to reply, Tab to move through the queue, Esc to leave one waiting and stop it reopening, q to close. It closes itself when the queue empties, however the asks were answered.
- Only the operator closes an ask. A teammate replying to a question is a peer note on the same thread; it may be useful, it is not an answer. That distinction is the whole point, and `herdr_team/asks.py` is the single place that decides it, because nothing in the schema ever said so — `kind: "answer"` exists in the enum and no code branched on it.
- `post --wait` blocks until you reply. It needs nothing special per agent kind, because every agent is already waiting on a shell command. Two things it does that `say --wait` does not: it polls a non-persisting `BoardTailer`, which reads only new bytes, instead of `BoardStore.read`, which re-parses up to 4 MB on every call; and it releases the team lock before waiting, so a member waiting for minutes never fails everyone else's post with `board_locked`.
- The wait is capped at nine minutes whatever you ask for. Claude Code kills a shell command at ten, and a longer wait would end as a killed process with no error the agent could read. Giving up is exit **6** (`wait_no_answer`), distinct from "refused" so an agent can tell the two apart without reading prose; the question stays on the board, and skill v7 tells the agent not to guess and never to take a teammate's reply as yours.
- `ask-policy`, and `/ask-policy` in the team console, set it per team: whether agents wait, on which kinds, for how long, and whether the popup opens at all. Blocking defaults to `question`, `blocked` and `request` — the popup fires on anything addressed to you, but blocking a `done` notice for eight minutes would freeze a team that posted forty of them in three days.
- The policy lives at `config.ask` and deliberately not under `config.gate`, whose keys are whitelisted: one unknown key there throws the entire gate config back to its defaults rather than erroring, and a test pins that this does not happen.
- A busy popup slot is an ordinary answer, not a failure. The notifier backs off and tries again rather than fighting the operator for the one slot, and it never calls `popup.close`, which would shut whatever you had open.

## 0.11.0 (2026-09-08)

- `herdr-synapse orient` hands a member the team back in one command: its name, role and team, the charter, its brief, its own instructions, the team rules, its teammates with the manager marked, where the team's files are, and its unread count. Findings stay a count and a command — they are peer notes, and inlining them would let one member's text reach another as though it carried authority.
- It calls the Claude session-start builder rather than composing its own text. That block is exactly what every kind needs and it was already built correctly; it was just wired to a door only Claude has. One builder, two callers, pinned byte-identical by a test, because a drift between them would surface precisely when an agent is already lost.
- A compacted Codex or OpenCode member is re-briefed at last. Claude reports a session phase change after a `/compact` and was handled; the other two report nothing, and the only sign is their token count falling. That was detected and recorded and then acted on by nothing — so the two kinds with no hooks, for which the typed line is the only channel there is, were exactly the ones that got nothing back.
- The once-only re-brief allowance is per briefing again. `rt.rebriefed` was set and never reset, so the second clear or compaction of a member's life got one attempt at an unacknowledged briefing and then gave up for as long as the notifier lived.
- The typed briefing names `orient` instead of four commands. One command an agent will run beats four it might, and it is 19 characters shorter — which does not show up as slack, because the degradation ladder always fills the 400-char budget, but as charter text: at the longest legal name and role a member now reads 51 characters of what the team is for instead of 32.
- `doctor` says when there would be nothing to hand back: a team with no rules, and members with empty instruction documents. On the team this was built against that is all three members and the rules both, which is why the answer to "is there a per-team file everybody gets" felt like no. There is one — the Rules half of `knowledge.md`, operator-authored and read by every member — and it had never been written.
- Skill v6 tells every agent to run `orient` after a compact or a clear, before anything else.

## 0.10.0 (2026-09-08)

- You can delete a team from the team view: `x` on a team row, or on any of its members. It asks first, and the question names what actually happens, because "dissolve" does not say it — the agents keep running and the board is archived to the session's `_archive/` rather than removed, so it is recoverable by moving the directory back. Enter is deliberately not the confirmation key, since Enter is what opens menus a row above.
- `dissolve` asks on a terminal instead of refusing. It used to demand `--yes` every time and error out otherwise, which read as the command not working; off a terminal `--yes` is still required, because there is nobody to ask. Declining exits 0 and changes nothing.

- A team can have a **manager**: one member the others are told coordinates the work. `herdr-synapse manager <name>`, `create --manager`, or action 8 on a member row in the team view, which toggles. At most one holder, enforced by the setter rather than the schema — the write that sets one clears every other. It is a boolean on the member, so a rename carries it and a removal drops it, and an existing roster loads as having none.
- Every agent is told, and told what it means. A `manager_changed` record names each member, `who` tags the row, `me` marks the teammate and tells the manager it is one, the Claude session-start blob names it in the teammate list, and the typed briefing marks it in the roster. Skill v5: take its assignments and handoffs as the plan unless they conflict with the charter, your own instructions, or something unsafe, and disagree on the board rather than quietly doing something else.
- Its posts to the whole team wake everyone. A broadcast from any other agent is held by gate 2 and waits for each member's next board read, which measured a 42-minute median on a live team — not a way to hand out scope. This lifts that one hold and nothing else; it deliberately does not route through `urgent`, which would also bypass the done-hold and the per-member interval, so a manager's broadcast is still subject to every rate limit, an open dialog, a draft and a blocked agent.
- It grants nothing by itself. The charter, the team rules and every member's instructions stay human-only, and `--operator` is the one way to add them, through the existing grant with its expiry, board announcement and per-use audit line. Appointing a manager is allowed to a delegated operator; granting authority is not, because a delegate must not be able to pass its own on.
- A system record does not deliver itself, which is the bug this shipped with for one afternoon. `_ingest_record` returns early for `from: system`, so addressing every member by name achieved nothing and naming the human achieved nothing: the record sat on the board, no agent was nudged for it, and the operator who had just set a manager saw no notification at all. Two lists fix it — `URGENT_SYSTEM_EVENTS` fans it out to the members, `TOAST_SYSTEM_EVENTS` reaches the operator's toast queue — and a test now asserts both halves together, because writing a record and delivering one are different things and only the first was covered.
- Skill v5 fits the same 150-line budget; the briefing's worst legal case is unchanged at 371 of 400 characters, and a roster too long to fit collapses to the count form rather than dropping a member's briefing.

## 0.9.0 (2026-09-08)

- Every member now shows how full its context window is, read from the harness's own files rather than guessed or scraped. Claude's transcript, Codex's rollout log and OpenCode's database all carry exact token counts; Codex carries the window size too. `herdr-synapse context` prints the report, `who` tags each member `context 94%`, and the notifier publishes it as a sidebar token that turns yellow at 75 % and red at 90 %. The readers tail their files instead of parsing them, and open SQLite read-only, because these files run to tens of megabytes on a working machine. A kind with no reader says `unknown` rather than inventing a number.
- Crossing 75 % and then 90 % puts one `context_high` record on the board addressed to the member and to the team. It says so once per crossing, not every fifteen seconds, and it never acts: what to do about a full context is the member's decision or yours.
- `herdr-synapse compact <name>` and `clear <name>` type the kind's own command into a member. Claude and Codex and OpenCode all take `/compact`; for clearing, Claude takes `/clear` while Codex and OpenCode take `/new`, because Codex's `/clear` also wipes the scrollback that Herdr's detection layer reads. A member may compact itself with `--self`; clearing is yours alone, and asks before it runs. A member that wants a peer compacted posts a request, exactly as before: no agent gains a way to type into another.
- The keystroke goes in as raw text plus a separate Enter, not as a prompt. `agent.prompt` sends a bracketed paste, and a pasted `/compact` arrives at a TUI agent as text to answer rather than a command to run. Delivery still goes through the whole gate: a blocked member, an open dialog, a draft on the prompt line or the wrong occupant all hold it, and idle is required, so a control keystroke never lands inside a running turn.
- Claude's compaction blocks its pane for two to three minutes, so the job is not finished when the keystroke lands. It stays open until the effect is actually visible, and is never typed twice. Six minutes with nothing observed closes it with a note rather than a retry.
- A compaction and a restart are no longer the same event. Claude reports `source=compact` against the same session id after a `/compact`, and the plugin read any change to that record as a new session: a new generation, a "restarted" line on the board. Identity is the session value now, and the source is only the phase it is in, so a compaction reads as a compaction, keeps the member's generation, and still re-briefs, because the briefing was in the history that was just summarized. A deliberate clear is recorded as one, naming who asked, instead of looking like a crash.
- A compaction nobody asked for is recorded too. A member's token count can only rise during a turn, so a large fall means the summary replaced the history; the board says so, because a teammate needs to know that this member now works from a summary.
- Skill v4 tells every agent to watch its own context: when the board says you are high, finish or hand off first and then compact, ask a teammate to compact by posting a request, and never clear anyone, yourself included.
- Every pane Herdr launches for the plugin had been reading an empty state directory since the 0.8.0 rename, and reported "no teams". Herdr sets `HERDR_PLUGIN_STATE_DIR` to `<state>/plugins/<plugin id>` on those panes, the rename changed the id, and the plugin ranked that variable above the pointer file that says where the data actually is. So the console, compose, the picker and the popups looked in the new empty directory while a shell and the notifier read the real one through the pointer. The pointer now outranks the value Herdr derives from the id; a value Herdr did not derive is still a deliberate redirection and still wins. Verified live: with the variable set the way Herdr sets it, `teams` now lists the running team instead of nothing.
- The team folder in your project is `.herdr-synapse/` now. The old `.herdr-team/` is renamed on the next render, artifacts and all — only ever a rename, and only into a name nothing occupies, because that folder holds real work and merging two of them is not something to attempt on your behalf. A path under the old name still resolves as inside the folder, so a `--ref` an agent wrote from memory does not start failing the moment it moves.
- Every member is told where it went. The `workdir_moved` record names the new knowledge base, the member's own document and the artifacts directory, and is addressed to each member by name as well as to the team: a record addressed only to `all` is a broadcast the delivery gate holds, so naming them is what actually gets each one nudged about the one thing every one of them is carrying a stale copy of.
- The state directory is `plugins/herdr-synapse` too. Nothing to run: the notifier follows the pointer it already wrote and rewrites it in place.
- `system_record` refuses to let a caller's extra detail overwrite the record's own fields. Writing the move record with `{"from": <path>}` replaced the author of a system record with a filesystem path; the store caught that one, but a collision on `text` would have gone through silently.
- The Claude hook shim gets the plugin id from the installer instead of naming it itself. Its fallback log location is the plugin state directory, whose last segment is the id, and the 0.8.0 rename left that line naming the previous one; a session whose state had moved logged nowhere. Reinstall with `herdr-synapse hooks install claude` (shim version 2).
- Generated files in your project folder say `herdr-synapse:workdir` instead of `herdr-team:workdir`. The old marker stays recognised, or a file wearing it would read as somebody else's and never be touched again. The version deliberately did not move with the name: bumping it would have made every old file answer "an older plugin wrote this, not a human", and an edit you had in flight when you upgraded would have been overwritten. Left where it is, the recorded digest still decides, so an untouched file is rewritten under the new name and an edited one waits for `instructions --adopt` exactly as before. The live team's folder migrated on the next render with nothing held.
- Not yet verified live: whether a running agent treats the typed `/compact` as its own slash command. The transport is settled by reading upstream, where `pane.send_text` writes bytes unwrapped and everything prompt-shaped brackets them as a paste, and everything around the keystroke is covered by tests. The last step needs a disposable session with real agents, so watch the first use of each kind.
- One severity name was spelled two different ways, which is why this shipped with tests rather than without. The threshold check compared against `warn` while the source of truth returned `warning`, so the comparison never matched and the warning it guarded could never have fired.

## 0.8.0 (2026-09-07)

- Renamed to **herdr-synapse**. Three GitHub repositories were called `herdr-team`, none of the other two an actual Herdr plugin, and in a marketplace of 968 auto-indexed plugins a name that returns three results and describes a category rather than a product is not a name. The plugin id, the CLI, the actions, the bundled skill and the Claude hook script all move; run `herdr plugin link` (or reinstall) once, then `herdr-synapse install-cli --yes`, `herdr-synapse skill install`, `herdr-synapse hooks install claude`, and `herdr-synapse daemon start --replace`.
- Nothing you own moves with it. Teams, boards, cursors, consoles, the `.herdr-team/` folder in your projects and the `HERDR_TEAM_*` variables injected into agent panes all keep their names, and a pointer file written under the new plugin id keeps the state root exactly where it was. Upgrading touched no team data here: the live team came through with all 680 board records and three bound members.
- The typed markers stay `[herdr-team …]` for now. They are the prefix the echo guard, the hooks and the skill all match on, so changing them is a separate migration rather than a rename.
- Naming the CLI once in the briefing instead of five times fixed a real limit found while renaming. At the maximum name, role and team lengths the briefing came to 444 characters against a 400-character budget, so the daemon logged "cannot brief at all" and that member was never briefed. The worst legal case now fits, and a test pins it.

## 0.7.0 (2026-09-07)

- Unsetting one environment variable no longer makes an agent the operator. Every human-only gate tested that the author was *named* `human`, and identity was decided by `HERDR_PANE_ID`, so `env -u HERDR_PANE_ID herdr-synapse knowledge set "..."` from any member wrote text that reached its teammates carrying operator authority. Identity now comes from the process tree: a pane-less caller that descends from an agent's pane is resolved as that agent, and so is one pointing at a shell pane it does not actually run in. Verified live on a real team before and after.
- The check is inconclusive by design when it cannot see. An unreachable server, a missing `ps`, or a pane that reports no usable process leaves the caller exactly where it was. Refusing on a failed lookup would have locked the operator out of their own CLI, which is worse than the hole. A pane reporting process id 1 no longer matches every caller, since init is everyone's ancestor.
- `herdr-synapse operator grant <name>` is the sanctioned way to let an agent build and run a team end to end. A delegated member may write the charter, the team rules, any member's instructions and the project folder; every such write is audited as `operator_action` naming the member, the grant and its withdrawal are announced on the board, `who` tags the member `acts as operator`, and `doctor` warns while any grant is live. Grants expire after 12 hours unless `--ttl 0` says otherwise, and `operator revoke` ends one early.
- Granting is the operator's alone. A delegated member passes every other gate and is refused at this one, so authority cannot be passed on, and a delegation is never inferred from a claimed identity: `HERDR_TEAM_MEMBER` names a member without proving anything, so an author resolved that way never carries a grant. `say` is unchanged and still requires a verified, focused console.
- None of this is a sandbox, and the docs say so. An agent that can run a shell as your user can reach the same files you can, the grant file included. What changed is that the obvious route is closed, the intended one is explicit, expiring and revocable, and every privileged action names who took it.

## 0.6.0 (2026-09-07)

- Each member's file is a real document you can edit. It has six sections, all optional, each with a line of guidance that rides in an HTML comment: Mission, Scope, Constraints, Definition of done, Handoffs, and Notes, which is private and never sent to the agent. A heading the plugin does not know is kept in place, so nothing you write is lost. Plain text with no headings becomes the Mission, so `--set "one sentence"` behaves as before and a pre-0.6 file needs no migration. Team creation seeds Mission from each member's brief, so nobody starts at "none set".
- The file in your project is no longer overwritten. Editing `members/<name>.md` used to be pointless: the notifier regenerated it within about ten seconds and reported the loss as "drift". Now an edit is kept, the notifier posts one `instructions_edited` record to you, and `herdr-synapse instructions <name> --adopt` shows a unified diff and applies it. `--discard` throws it away, `--edit` opens the document in `$EDITOR` the way `charter edit` already did.
- Adopting is what confers authority, and that is deliberate. The folder sits in a checkout the agents themselves can write to, and the plugin cannot tell whose editor saved the file, so nothing there reaches an agent until a human adopts it. The property that a forged mirror never reaches anyone still holds and is still pinned by a test.
- Telling an edit from a template change needs more than a diff against what the plugin would write now, since both cases differ from the file on disk. The digest of what was last written is recorded per file, so a plugin-side format change still regenerates while your edit is left alone. Without this a member that left the team would have kept its old document instead of its tombstone.
- A changed document now reaches its member. A Claude member gets it spliced into its next turn and only until it acknowledges, so it costs context once rather than every turn. Every other kind gets the ordinary nudge, because the `instructions_updated` record now names the member as well as `all`: a record addressed only to `all` is a broadcast, which the delivery gate holds, so the one member whose job had changed was never nudged about it. `who` shows `instructions: stale` until `ack`, which now records the charter, the instructions and the rules together.
- The typed briefing names `herdr-synapse instructions`, and the skill (v3) tells every agent to read its document at session start and whenever the board says it changed. For a kind without hooks that line is the only push channel there is; nothing had ever told those agents the document existed.
- Two different files were called `knowledge.md`: the state copy held the rules, the project mirror held the rules plus every finding, and agents told to "read knowledge.md" could reach either. The state copy is now `rules.md`. The old name is still read when it is the only one present and is removed on the first write.
- The cold-start replay used its own two-event whitelist rather than the shared one, so an urgent instructions or rules change made while the notifier was down was silently dropped on restart. That window opens on every plugin upgrade, since the notifier exits when the version changes.
- `project set` announces the folder on the board. Members that joined before it existed had no way to learn it was there.
- Smaller repairs: an instructions or rules file over the limit is refused rather than silently truncated mid-sentence, `--set` and `--file` together are refused rather than one silently winning, a foreign or pending `members/<name>.md` shows up in `knowledge-status` and the tree, `me` prints the paths of the knowledge base and the board snapshot rather than leaving you to join two lines, and the status views say "2/3 with instructions" instead of "2/3 briefed", which meant something else on the same screen.

## 0.5.0 (2026-09-07)

- A member is tied to its harness session. Herdr already reports one per pane through each harness's integration (`agent_session` on every `agent list` row: `herdr:claude`, `herdr:codex`, `herdr:opencode`) and its own restore reopens exactly that session; the plugin received it on every 2-second poll and discarded it, `Member.session` was declared and never written, and the Claude hook's `session_id` was captured into the pane record and never read. The roster now records it at join, bind, and on every poll, and shows its tail in `who`, `me` and the `prefix+t` tree.
- Rehydration matches on the session first, before terminal id, label, pane id, name and the `(kind, cwd, workspace)` fingerprint. Two agents of one kind in one directory — the case the fingerprint step could only refuse — bind back to the right panes after a cold restart, and a pane carrying another member's label no longer wins over the session. The daemon's reconcile and the hook slow path apply the same rule; a member with no recorded session behaves exactly as before.
- A fresh agent in a member's pane is detected. Terminal ids survive a crash, so a brand-new Claude, Codex or OpenCode started in a member's pane used to wear the member's name with no briefing and no memory of who it was. A different session on the member's own terminal now bumps the generation, posts `member_restarted` naming both sessions, clears `briefed_at` and enqueues a briefing; name, pane and read position stay. A compaction re-reports the same id and changes nothing. The Claude `SessionStart` hook is a second channel for the same id, so a Claude member is caught even when Herdr kept a stale one (it refuses a `startup` report while one is held). A session change on a known terminal makes the poll reconcile at once instead of on the 10-second timer.
- The resume table covers every integration Herdr ships, all 17 of them (claude, codex, copilot, cursor, devin, droid, grok, hermes, kilo, kimi, mastracode, omp, opencode, pi, qodercli, qwen, agy), copied entry for entry from `src/agent_resume.rs` and pinned by a test, since an entry that drifts from Herdr resumes the wrong thing or nothing. Pi and omp identify a session by an absolute path rather than an id, and both reference kinds are carried end to end. A source Herdr does not issue, or one paired with an agent Herdr never pairs it with, is refused rather than guessed. Session values follow Herdr's own validators (bounded, no control characters, absolute for a path) with one addition: a value starting with `-` is refused, because `resume` puts it in an `execvp` argv where a leading dash would be read as a flag. An unusable value is refused rather than trimmed, since a truncated id is a wrong id.
- `herdr-synapse resume <name>` reopens a member's own conversation. `claude --continue`, `codex resume --last` and `opencode -c` pick by directory or recency, never by pane, so with several members in one checkout any of them could come back under a member's name. `resume` runs the same command Herdr uses on restore (`claude --resume <id>`, `codex resume <id>`, `opencode --session <id>`) from the member's directory and replaces the shell with it; the harness reports the session for that pane and the notifier rebinds the member there by it. Human only; `--print` shows the command, which is what action 7 on a member in `prefix+t` does. It refuses a member with no recorded session, a kind with no known resume command, a pane that is not a shell, and a member still running that session elsewhere.
- Pane records (`panes/<terminal_id>.json`) carry the session and are garbage-collected: every Herdr restart reallocates terminal ids and used to leave one orphaned record per member behind.

## 0.4.2 (2026-09-07)

- The board is saved into the team folder automatically. `<project>/.herdr-team/<team>/board.md` holds the whole board, archived segments included, beside the team's rules and per-member instructions, so the folder carries the conversation and not just the documents. The notifier rewrites it when the board has actually moved, at most once a minute.
- The snapshot's content is a pure function of the board — it is stamped with the newest post's timestamp rather than the current time — so an unchanged board never rewrites the file or shows up as a change.
- `board.md` is added to the generated `.gitignore`, and the ignore rule is written before the file is, so a snapshot created under an older folder layout is never briefly committable. It is marker-protected like the other mirrors: a file the plugin did not write is left alone.
- Generated mirrors are capped at 64 KB to stop a pathological document filling a repo; the board snapshot gets its own 8 MB budget, since at 64 KB a real team's board was cut in half.

## 0.4.1 (2026-09-07)

- Team names may be up to 32 characters (was 15) and roles up to 64 (was 32). A real team was sitting exactly on both ceilings: `clickhouse-hunt` is 15 and `vulnerability-researcher-manager` is 32.
- Member names stay at 32, which is not a plugin limit: a member name *is* its Herdr agent name, and Herdr rejects anything longer (`valid_agent_name`, `src/app/agents.rs`).
- `fit_member_name` gives the role priority. It used to trim only the role and then hard-clip the whole string, which was fine while teams were capped at 15 but with a longer team truncated the team itself — so every member of `clickhouse-vulnerability-hunt` derived the *same* name. The team prefix now gives way instead, dropping whole trailing segments before any clipping, so `clickhouse-vulnerability-hunt` yields `clickhouse-vulnerability-manager` and `clickhouse-reviewer` rather than two identical names.
- The limits are read off the patterns, so the error messages and the picker's hint cannot drift from them again.

## 0.4.0 (2026-09-07)

- A team's board can be opened, not only switched to, and several can be open at once in the same space. `herdr-synapse ui console --team <name>` opens that team's board; a second open for a team that already has one focuses it instead. `prefix+u` opens the default team's board, and `b` on a team row in `prefix+t` opens that team's. Each console is pinned to the team it was opened for, and its pane is labelled `Team console: <team>`.
- `/use <team>` in a console now **opens** that team's board beside the current one instead of switching the pane under you. It also no longer rewrites the session-wide default team, which used to change team inference for every other console, popup and shell in the session.
- `console.json` is a registry keyed by terminal id rather than a single record. This is what made a second console impossible: the one recorded `terminal_id` was also the proof that a process is the console, so opening a second one overwrote it and silently demoted the first to `cli-unverified` (HP-07). A pre-registry file is read as a one-entry registry, so no migration is needed. Registry writes take a lock, because several console processes write the file now.
- `say` and verified human posts accept any live registered console rather than one recorded terminal. The real gates are unchanged: the pane must still be focused and the caller must still be a descendant of it, and Herdr's focus is session-wide, so exactly one board is say-capable at a time — the one you are looking at.
- `reconcile_console` no longer closes a live console it does not recognise, closes each console on its own evidence, and reopens each recorded console on its own team.
- `/as` sets the label of the console you typed it in, so it no longer re-points another board's unread cursor.

## 0.3.1 (2026-09-07)

- An idle agent no longer sits on mail nothing will ever wake it for. A post addressed to `all` creates no pending unless it is urgent or you wrote it, and every agent-side read path is turn-triggered, so an idle member holding only a teammate's broadcast stayed asleep indefinitely: measured on a live team, a member's broadcast took a **median of 42 minutes** to reach everyone and 11 of 47 never reached someone at all. The notifier now sweeps for members that are idle with unread posts and creates an ordinary pending, at most once per member every three minutes. Broadcasts still do not interrupt: the swept nudge is not urgent, so every gate (done_hold, focus, dialogs, drafts) still applies, and a chatty team costs one nudge per member per interval rather than one per post.
- The sweep applies the same reader rule as the ingest path, so a record that renders `(unverified)` can never be laundered into a nudge through it.
- `knowledge set --urgent` and `instructions --set --urgent` now nudge, as `docs/cli.md` always claimed they did. The daemon whitelisted only `charter_updated` and `member_joined`, so both flags set the record field and did nothing. Shipped broken in 0.2.0.

## 0.3.0 (2026-09-06)

- Typing `/` in the console opens a menu of every command with its placeholder and what it does, the way `@`, `@@` and `!` already did for names, files and members. Type to narrow it, arrows move, Tab completes the command without the placeholder, Esc hides it. Enter still runs the line you typed, so a fully typed command never needs a second press. The compose popup offers only the post directives it can actually parse.
- `herdr-synapse export` saves the whole board to a file, rotated archive segments included, so a finished team leaves a record that outlives its session. Markdown by default (a standalone document with the charter and roster the posts refer to, then every post with its sender, recipients, kind, refs and reply links), plus `json`, `jsonl` (the raw on-disk shape, so it reads back into anything) and `text`. `--since`, `--last`, `--kind` and `--from` narrow it; `--stdout` pipes it; an existing file is refused without `--force` and symlinked targets are refused outright.
- `/export [path] [--format …]` does the same from the team console, which is where you are when you decide you want to keep the board. With no path it writes into the team folder's `exports/` (git-ignored), or your home directory when the team has no folder — never the console pane's own working directory, which is the plugin's.

## 0.2.1 (2026-09-06)

- The console feed follows the newest post again, and says so when it does not. `Up` scrolled the feed and the offset was carried across every refresh for ever, so one keypress left you permanently behind the tail with nothing on screen explaining it — on a live team the console sat on record #64 while the board was at #68. Scrolling back now shows a `4 newer below · End returns to the latest` rule, `End` or `Esc` jumps back, reaching the bottom resumes following, and posting snaps to the latest.
- The console's 250 ms refresh can no longer be lost. `nodelay(False)` is ncurses' *blocking* mode and does not restore a timeout set earlier, so the first `Esc`, paste, or unrecognised escape sequence stopped the console updating until the next keypress. The tick is now re-armed every pass, the refresh runs off the wall clock rather than off an idle key, and `Esc` no longer costs ncurses' default one-second delay. The picker, compose and usage popups had the same defect and are fixed too.
- An idle console no longer re-formats the whole board four times a second: 17.3% CPU at 300 records becomes 0.09%. A ~12-stat signature over everything the model reads gates the rebuild, with a 5 s backstop so relative timestamps keep moving.
- `artifacts_changed` records are short. Listing up to 8 paths per category produced 1003-character records on a real team — twice what the skill asks agents for, and a quarter of the context block every member shares. Records are now summarised by directory and capped at 220 characters: a 40-file data dump reads `artifacts: new 40 files under codex-hunt-researcher/…/victim/`, while a single report is still named in full.
- The artifacts watcher waits for a tree to stop changing before posting, so a build or a data dump is one record instead of one every ten seconds, with a five-minute ceiling for a tree that never settles and a one-minute floor between records. Deferring is lossless: the diff baseline is what the board was last told, not the last scan. `config.artifacts.watch = false` in `team.json` turns it off per team.
- An `artifacts_changed` record no longer holds Claude's Stop hook open. It counted as unread mail, so a teammate saving a file could send a member that had finished its turn back to the board. It still reaches `board --new` and the prompt-submit context.
- A large drop into `artifacts/` no longer makes the watcher announce files as removed that were never deleted. The fingerprint stopped mid-walk at 500 entries, so a 600-file dump evicted a real report from it; deep and wide subtrees are now collapsed to one entry instead.

## 0.2.0 (2026-09-06)

- A team can have a working directory in your project. `herdr-synapse project set <path>` records it and creates `<path>/.herdr-team/<team>/`, namespaced so two teams can share one project. It holds `knowledge.md`, a `members/<name>.md` per member, and an `artifacts/` directory members own outright, plus a generated `README.md` and `.gitignore` above them. `herdr-synapse me` prints the absolute paths, which matters because members of one team routinely sit in different checkouts. The plugin never infers the directory and writes nothing into a project until you set it.
- `prefix+f` (`knowledge-status`, `ui knowledge`) shows every team's knowledge base at a glance, the way `prefix+i` shows usage: folder, rules, which members have instructions, findings, artifacts, and any problem. A team with no folder is printed with the command that gives it one.
- The `prefix+t` tree marks a team that has no folder, its detail line summarises the one that does, and `f` on a team row sets or changes the folder without leaving the popup, prefilled with the directory that team's members share.
- A team can be set up in one step. `create` takes `--project <path>`, `--rules "…"` / `--rules-file`, and `--instructions NAME=TEXT`, and the `prefix+t` wizard has a folder stage that prefills the directory the selected agents already share (Tab skips it). Without `--project`, `create` prints the directory the members share and the exact `project set` command rather than acting on it.
- Per-member instructions: `herdr-synapse instructions <name> --set "…"` (human only) is the long form of a brief, up to 4000 characters. Agents sharing a checkout read the same `CLAUDE.md`; this is what makes their jobs different. Claude members also receive it in their session context.
- A knowledge base per team: `herdr-synapse knowledge set "…"` (human only) holds the DOs and DON'Ts and carries operator authority, and `herdr-synapse knowledge add "<text>"` lets any member append an attributed finding. Rules and findings are deliberately separate authorities: a finding is escaped, is pointed at rather than injected, and can never reach a teammate as an instruction.
- Nothing under a project directory is ever deleted. Removing a member writes a tombstone over its file, renaming one leaves a forwarding note under the old name, and a file the plugin did not write is never overwritten without `--force`.
- The Claude session-start context block is now escaped line by line and capped. It previously interpolated the member's brief raw into text that reaches Claude unfenced.
- A member whose name, role, team and teammates overflowed the 400-character briefing budget was never briefed at all: the error escaped the enqueue path's handler. It now falls back to the short briefing and logs why.
- Changes reach agents instead of only landing on disk. Every rules edit, instructions change, finding, and file added to `artifacts/` appends a board record, so Claude picks it up on its next prompt through the prompt-submit hook and every other kind on its next board read. These are broadcast records, so they deliberately do not nudge anyone mid-turn; `--urgent` on `knowledge set` and `instructions --set` is the opt-in that does.
- The notifier watches the team's `artifacts/` tree and posts one batched record when files are added, changed, or removed, whoever did it: a member, you by hand, or another tool. The first scan after a start only seeds the fingerprint, so a restart never re-announces existing files.
- The skill is v2 and teaches the folder, the member's own instructions file, and the knowledge base.
